# Original UBA launches original Apple Clang after library-path compaction

Stage104 host VM statistics lets the original UE UBA scheduler proceed: the original Xcode game attempt reports nonzero physical memory use, queues 804 actions, and starts Apple Clang. Twenty-three compiler processes then abort early. Original Swift actions also run, but the UE build finishes with OtherCompilationError and Xcode status 75. This is progress past the scheduler wait, not a completed game build.

A focused reproduction uses the original Mac `UbaCli` and original Apple Clang on one small C source targeting iOS arm64. Clang invoked directly succeeds. Through UBA it reaches the stack protector failure, with a captured call chain through UBA `ProcessCreator::SendMessage`, libc `__stack_chk_fail`, and `__abort`. The diagnostic debugger intervened in the focused failing run; the separate full Xcode attempt independently observed compiler SIGABRT failures. Original logs and the signal capture remain private.

Our composed research environment supplies library search paths of 4,046 / 4,649 bytes. The original UBA child-process path appends this value to a fixed 1,024-byte temporary buffer; release-mode append does not check its capacity. This is an integration-environment problem, not evidence that Darling lacks a compiler API. No UBA, Clang or engine implementation is modified.

The new optional profile selector groups consecutive workspace library directories into private link directories. The first matching basename from each ordered group is retained, and non-workspace fallback directories keep their positions. Each link points to the same original entry; contents and existing search directories are preserved. The resulting paths are 236 bytes in the focused run. Framework lookup is unchanged. This option is tested for the original Intel UBA/Clang workflow; it does not claim universal equivalence for every possible loader fallback or @loader_path layout.

With this single environment change, original UBA local execution returns native/outer zero and creates a real Mach-O arm64 relocatable object. Its SHA256 is identical to the direct-Clang object from the same source. The full original Xcode UE invocation is resumed separately using `--compact-library-paths` in our research launcher. The user's Xcode command, workspace, scheme and original build tools are preserved. Full UE App compilation, signing and UE CocoaPods remain pending; the frozen Unity certificate candidate is not changed.

Run the attached `probe-original-uba-clang.py --stage artifacts/private-procfs-auditsession104-stage.json` to reproduce the long-path input, and add `--compact-library-paths` for the corrected environment. It uses the existing private temporary-filesystem selector and native session lock. Apple/Epic binaries, source contents, raw original tool logs, cores and credentials are excluded. This package requires the existing research runtime and is not a cold installer.
