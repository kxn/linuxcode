# Fresh Linux Unity export, CocoaPods, original Xcode build and signed App

A newly created Unity6000.3.27f1 project was exported by the official native Linux Editor without a graphical display or any Mac. The genuine export generated424 C++ files and a local native CocoaPods fixture. Original Darwin CocoaPods installed LinuxcodeSmoke and generated the workspace. Original xcodebuild compiled48 native tasks, completed282 IL2CPP updates out of283 evaluated tasks, and executed5 original CodeSign tasks for iPhoneOS arm64.

The first native build returned0 but Darling server crashed during service cleanup, so that surrounding CI invocation failed. Its output, failed report and private core remain retained. Signal trace RPCs were replaced by the direct Linux writer and the process-local stop defect was fixed; the new runtime passed focused child-wait, concurrent signal/state-read and fatal-child tests. The retry uses guarded reflink copies and workspace mappings, retaining the original project, App and build database byte for byte. It reuses completed compilation, and the original build plus surrounding environment now both return0. This is not claimed as a single invocation that freshly compiled and completed all cleanup steps.

Original codesign --verify --strict succeeds for LinuxcodeExportSmoke.app and its embedded UnityFramework.framework. An independent checker verifies17+8873 code pages and32+2 sealed resources respectively. The resulting UnityFramework actually defines _LinuxcodePodAnswer, proving that the Pod native function linked. The iPhone and iPad launch screens produced four NIBs and Assets.car is retained with its digest. Main binary metadata confirms iPhoneOS arm64 and org.linuxcode.exportsmoke. These are ad-hoc signatures; no zsign is used. Apple developer provisioning, device execution, UE application building and cold installation are not established by this record.

The earlier unity-editor-export-and-p12 research directory contains the real fixture, official Editor/module acquisition, preparation and export drivers. The waitid-and-signal-diagnostics directory preserves the source/runtime fix and guarded build recovery driver. The sanitized milestone excludes Unity licensing/authentication logs and all runtime/game binaries. Original native build and signature reports remain separately inspectable.
