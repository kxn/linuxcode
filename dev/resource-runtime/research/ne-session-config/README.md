# NetworkExtension configuration presence queries for original UBT

Original UnrealBuildTool runs using Epic's macOS Intel .NET10.0.203 under Darling. After the GC, private temporary filesystem and waitid fixes, first-run SDK setup reached ASP.NET developer-certificate enumeration in the legacy keychain implementation. A saved native stack establishes that this is Microsoft.AspNetCore.DeveloperCertificates.XPlat setup. The driver now uses Microsoft's documented DOTNET_GENERATE_ASPNET_CERTIFICATE=false for this non-ASP.NET build. Original build arguments remain unchanged; application signing and TLS certificate validation are not disabled.

The next original failure was SystemConfiguration importing ne_session_app_vpn_configs_present. Inspection of the pinned original x86_64 NetworkExtension image establishes three related no-argument boolean queries over one cached notification state: App VPN bit62, always-on VPN bit61, and on-demand bit63. The state comes from com.apple.neconfigurationchanged through notify_register_check, notify_check and notify_get_state; errors cancel the token and clear state. The report retains the reference image digest and functional contract, not Apple code.

Darling source now implements all three queries over the real notification service, with a shared synchronized cache. Initial registration is lazy to avoid a libSystem initialization cycle. The native test verifies state setting/clearing, unrelated bits, retained cache without posting, change after posting, and a fresh exec child updating state observed by its parent. The earlier inherited notify-client registration after fork without exec fails in the existing backend and remains explicitly unverified; the test uses the exec startup path used by actual tools. Full VPN sessions and a NetworkExtension data path are not implemented by these presence queries.

The original UBT consumer advances beyond the missing NetworkExtension binding with configurationv153 and stage89, then fails because original Security.framework needs tls_handshake_create_for_caller from libcoretls. No successful UBT or UE App is claimed. Existing verified Unity configurations remain unchanged; their unaffected checks were not repeated. The changes are published in kxn/darling at e6b769a6, branch linuxcode/xcode-x86_64. The payload includes the source module, declaration/build integration, immutable staging helper, real-notify probe and unchanged-command original .NET driver.
