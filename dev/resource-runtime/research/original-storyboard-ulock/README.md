# Original Unity Storyboard compilation and real ulock waiter counts

Original ibtool now compiles Unity LaunchScreen-iPad.storyboard successfully under Linux/Darling, with the original IBAgent and no graphical session. Both a diagnostic run and a separate untraced run return zero and produce identical two NIB archives plus an entry-point Info.plist. Independent inspection verifies the NIB header table offsets and the entry mapping. Full visual/layout semantics and the complete App are not yet verified. Only hashes and metadata are included here; the proprietary product binaries remain private.

The preceding main-queue dispatch assertion came from the old ulock implementation returning a hard-coded positive one after every successful wait. The source now tracks actual waiters for process-private unfair-lock/compare-and-wait operations, returning the remaining count, including zero. The native test covers eight simultaneous waiters, wake-one/wake-all, timeout/error paths, opcode conflicts and fork while a parent waiter exists. Existing public lock contention passes 160000 increments in the same native session. Registry capacity is 1024 simultaneous addresses; Darwin priority inheritance, shared/64-bit waits and targeted-wake semantics are not claimed.

A failed first candidate exposed a separate existing ULF_NO_ERRNO wrapper mismatch. Both x86 syscall wrapper macros now decode the existing reserved error marker without changing errno; ordinary open/read error controls still pass. The failed candidate and corrected full source builds are retained. The diagnostic agent is killed during normal successful tool cleanup; this is not presented as a new crash.

The full incremental Unity/CocoaPods build reuses the existing DerivedData and original command. It has not completed: passive live stacks show SwiftPM waiting for xcrun --find metal, whose nested xcodebuild SDK query waits on CoreServices. CoreServices itself blocks on the first EVFILT_PROC notification recv after stale readiness. This is the next source repair, not a successful App claim. Source changes are preserved in kxn/darling-xnu on linuxcode/xcode-x86_64, committed as Comman Kang.
