# Original xcodebuild completes and signs a real Unity/CocoaPods App

On Linux x86_64, the original Xcode 26.6 xcodebuild returns 0 with `BUILD SUCCEEDED` for the real Unity-generated uEmuera workspace with CocoaPods/AFNetworking. It completes IL2CPP/Bee, arm64 linking, both original iPhone/iPad Storyboards, original actool asset compilation, three embedded Framework copies and signatures, Info.plist processing and final App CodeSign. The produced iPhoneOS/arm64 App uses ad-hoc signing with the original codesign, without zsign, a Mac or a graphical session.

The actual full-build report is `artifacts/xcode-service-runtime-tool-dispatch-diagnostic-build-9e1908267515.json`, using stage80 and direct-resource configuration150. Original `codesign --verify --strict --verbose=2` passes for all six selected products: uEmuera.app, embedded UnityFramework, libHarfBuzzSharp, libSkiaSharp, and both CocoaPods archives. Independent code-page/special-slot/resource checks pass, including 2,904 App resources, 26,153 UnityFramework pages, and every actual FAT slice of HarfBuzz (armv7 and arm64) and Skia (arm64). Extending the verifier to these real FAT inputs does not add host ARM support; all build tools still execute as x86_64 on Linux. Three memory-only code-page mutations (App and both HarfBuzz slices) are rejected. Generated products are unchanged by the controls.

The App contains four valid NIBArchive outputs and the real Assets.car produced by original actool. The preceding resource checkpoint bounds the CAR block tables and named trees and checks the exported icon dimensions and PNG chunk checksums. These checks do not establish visual rendering or device execution. The source sample is not a newly generated empty Unity project: it is the existing real Unity uEmuera project. Two explicitly recorded AFNetworking source imports were removed for SDK compatibility in a separate sample copy; the original Xcode project and CocoaPods configurations remain unchanged. Incremental build success reuses earlier verified compile products; this is not a new clean-DerivedData or clean-machine reconstruction claim.

The integration CLI now accepts `adopt --engine-milestone artifacts/unity-original-signed-app-v1.json` for this already assembled workspace. It selects the exact recorded source runtime and resource environment, verifies the build/product receipts and hashes, restores the recorded service prelude, and creates an xcodebuild PATH entry preserving the project's original arguments. The source installation and development environment remain separate from Darling itself. This option does not cold-build all historical compatibility components from a fresh XIP alone.

That actual generated PATH entry has also completed the same full Unity/CocoaPods build from the project directory, with the original argument vector and both native and outer exit codes zero. All milestone product hashes remain unchanged, so the completed signature checks are reused. The entry's two negative tests reject a receipt for another runtime and an executable changed after successful verification. Public packaging now also accepts the pinned source-only pthread aliases, syscall tables, include fragments and assembly files already present in historical checkpoints; private inputs remain outside the allowlist.

Remaining scope is explicit: ad-hoc signatures do not establish developer-certificate signing, provisioning or installation on an iOS device. UE, arbitrary projects, complete framework semantics, complete graphical APIs and cold reconstruction of this research runtime are not verified. The default older installation recipe is not silently replaced. This checkpoint contains source, textual evidence and hashes, without Xcode/SDK/Unity binaries, certificates, private keys or generated App/CAR/NIB/PNG products.

The normal CLI source package includes installation/development sources and documentation while omitting historical reference attachments. Use `package --include-research-history` to include those larger diagnostic records. The public package contents are checked against an explicit source allowlist.
