# Workloop event domains for original iOS libdispatch

Original libdispatch reached kevent_id, but Darling had no handler for BSD syscall375. Its first actual call registered a Mach port with WORKLOOP|ERROR_EVENTS|IMMEDIATE flags0x403, event flags0x385 and receive options0x0700400e. The new source implementation creates distinct event domains and hands actual Linux readiness and Mach messages to the paired pthread workloop callback ABI, including the ID immediately before the event array.

The first native two-domain test delivered64 pipe and64 Mach events with concurrent callbacks. The final test uses the original event and audit-trailer options: it verifies both domains, repeated event updates, processing-once/re-enable behavior, and32 real too-large-message/explicit-buffer retries per domain. Workloop capability is enabled only in the experimental paired variant after the native transport proof. Complete source builds compile907 kernel/backend units and13 pthread units.

The shared libkqueue update path now applies EV_ADD updates before an optional enable transition and avoids adding an already-enabled descriptor twice. The existing receipt/error/multichange/readiness fixture passes against this complete runtime, and GCD again completes9,216 tasks including parking/reuse/idle expiry. One earlier receipt attempt timed out waiting behind an active Darling session and produced no native output; it is preserved as a harness scheduling failure, followed by the actual serialized passing run.

Original IBAgent now creates real per-domain receive threads and advances beyond workloop registration. The next observed original assertion is voucher task initialization. A native characterization identifies two separate gaps: trap70 returns KERN_FAILURE5, while the real MIG Bank CREATE request returns KERN_INVALID_ARGUMENT4. An empty recipe returns the specified success/null. No successful Bank voucher, Storyboard or complete App is claimed.

This is an experimental event transport, not a complete Darwin workloop scheduler. Domains are bounded to64 and retained to process exit. Ownership-specific EVFILT_WORKLOOP commands and workloop_ctl policy are explicitly unsupported; arbitrary teardown/reuse, post-fork-without-exec, full FD lifecycle and Darwin scheduler/resource-accounting semantics require more work. The default CMake option stays off, and a cold complete Darling build remains unverified. Source, text evidence and hashes only; no Apple or SDK binaries.
