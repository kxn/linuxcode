# Asynchronous workloop requests

After Bank initialization, original libdispatch registered two real Mach ports successfully and then called EVFILT_WORKLOOP with NOTE_WL_THREAD_REQUEST | NOTE_WL_UPDATE_QOS | NOTE_WL_IGNORE_ESTALE. This was the exact unsupported operation, including the queue-state address, mask and expected value. The new source follows the paired open-source XNU async debounce/clear protocol, wakes a real Linux eventfd, and delivers the request through the existing serial domain pump. Input/output aliasing, observed-state error receipts, pending deletion and QoS updates are handled explicitly. Sync wait/wake/IPC and ownership modifiers remain unsupported.

The two-domain native fixture verifies stale and ignored-stale updates, inaccessible/unaligned addresses, invalid priority errors, 200 coalesced updates behind blocked callbacks, last-state delivery, deletion of a pending request, 64 real pipe events and ordered mixed receipts. The first fixture used an out-of-range QoS and correctly failed; the corrected fixture uses two valid classes and passes. The affected Mach regression also passes: 64 pipe events, 64 messages and 32 genuine large-message retries per domain. Unchanged Bank, signing and whole-workspace tests were not repeated.

The complete907-unit compile reached the original Apple linker but failed because a private priority helper needed its existing inline header implementation exposed. Recovery recompiles only the changed translation unit and reuses906 objects after checking the template source/header hashes, pinned repositories, generated path/timestamp differences, complete object list and export set. The failed link and recovery provenance remain separate.

Original IBAgent now passes asynchronous workloop scheduling and reaches original iOS libxpc, which traps on MACH_SEND_INVALID_OPTIONS while contacting preferences. The exact next mach_msg2 request is being diagnosed; no resource/App success is inferred. Domains remain bounded to64 and retained until process exit. Sync ownership/turnstiles, Darwin scheduler accounting, arbitrary domain lifecycle and full FD lifecycle are not established. UINT64_MAX is reserved for the private EVFILT_USER control registration. The default installer candidate is unchanged. Source and UTF-8 evidence only; no private Apple/SDK binaries.
