# Reliable Intel loader layouts and filesystem event persistence

A fresh DerivedData build exposes a failure hidden by the earlier incremental Unity/CocoaPods milestone: IL2CPP updates438 of443 tasks, but one original clang child exits before execution because its preferred64KiB Darwin main-stack address is occupied by the Linux initial stack. The missing il2cpp.a linker input is secondary. This is related to the fixed-address loader behavior documented in Darling issue1428, and the observed compiler here is x86_64.

The source loader preserves the usual stack address when available. On EEXIST it allocates a fallback entirely below the commpage, with a lazy reservation matching the finite stack limit (64MiB initial capacity for unlimited stacks). It never replaces the occupied mapping. A real Linux host test verifies preferred allocation, forced collision, full8MiB capacity and preservation of the occupied bytes. A native diagnostic reserves the preferred region before the loader runs: stage80 fails with the original EEXIST17, while the fixed loader runs the real Mach-O probe, exercises512KiB of main stack and a correctly sized pthread, and preserves the original mapping. LD_PRELOAD belongs only to this diagnostic fault injection; production uses the source-built loader without it.

The first native fixture incorrectly put a512KiB local array on a default512KiB worker stack. Its captured first fault identifies that worker overflow; selecting a1MiB test thread stack fixes the fixture without another main-stack allocation change. The failure and capture remain in the evidence.

After the main-stack fix, IL2CPP completes all443 tasks and produces its archive. Another original tool then exposes the complementary case: Linux's live argc/argv/environment storage overlaps the fixed commpage. Before any loader/RPC initialization, the loader checks the real initial-stack mapping and re-execs itself only for that live overlap, preserving PID, arguments, environment and inherited descriptors while letting the kernel choose another randomized layout. ASLR is not disabled; attempts are bounded at16. The private attempt variable is removed before Darwin userland starts. Retired stack pages retain their existing deferred-install path, and unrelated occupied mappings remain errors. A host test performs a real self-exec with the same PID, literal UTF-8 arguments/environment and a live pipe; it also checks the retry bound.

Separately, an isolated Linux test reproduces a filesystem feedback defect: the shared event journal's atomic `.darling-fsevents-id.pending` updates reach the legacy raw file-ID watcher as lost events. The backend now excludes only its own three reserved files at the prefix root. Genuine rename/delete events, matching names in nested directories and matching names outside the prefix scope remain observable. ASAN/UBSAN checks pass, along with337 existing raw-wire checks. This avoids creating file-ID invalidations from the journal's own persistence; it does not suppress genuine loss notifications.

Source changes are pushed as Comman Kang to the existing fork branches: Darling main-stack7548c765 and live-layout4f65c25f; darlingserver journal-filter7dea5cf. The original private server build output is restored after rebuilding. Stage83 combines the new loader and server while retaining the verified kernel/library pair. Its forced native stack check passes, and the previously fresh DerivedData build completes with original xcodebuild status0. A second completely absent DerivedData and absent Unity temporary-cache entry then succeed in one complete original xcodebuild invocation under the final source version. This run updates442 of443 IL2CPP tasks and executes58 CompileC tasks. Independent archive parsing confirms374 arm64 Mach-O objects in the newly generated Unity archives. All six original codesign strict verifications and independent signature seals pass. The unchanged integration CLI adopts this new milestone; the previous stage80 PATH-entry native build remains the separately recorded launcher verification.

Only source, text, hashes and metadata are published. Existing Xcode project/CI arguments are preserved except output-directory selection. The sample retains the documented two AFNetworking import removals for SDK compatibility. These fixes do not establish developer-certificate signing, provisioning, device execution, UE or clean-machine reconstruction of the entire research runtime.
