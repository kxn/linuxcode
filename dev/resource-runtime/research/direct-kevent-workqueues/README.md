# Direct event workqueues for original iOS components

The original iOS libdispatch first required workqueue maintenance support. After real direct event transport was added, it reached implicit kqueue creation and exposed a separate layout dependency: Darling had placed libkqueue inside its host libSystem, whereas the simulator loads Apple's original libSystem. The experimental source-kernel variant now embeds all17 libkqueue source units, rather than relying on absent host initializer objects.

A paired source pthread implementation uses a detached ordinary thread to receive real Linux readiness and hand it to registered Darwin kevent worker callbacks. Per-worker TSD replaces the old global pending-event pointer, with genuine completion handoff and worker reuse. The source kernel exposes only the implemented basic workqueue capabilities in this opt-in variant. Workloop, complete BSDTHREAD_CTL and SET_SELF capability bits remain clear.

Native evidence verifies256 pipe readiness callbacks,32 asynchronous Mach messages and192 regular/cooperative callbacks across all six QoS classes. All three backend entry points resolve inside the source kernel. Separate real Mach-message checks cover front and stack buffer placement, remaining-byte accounting, sentinels, inaccessible size pointers, a real too-large message retained in its port and a successful explicit-buffer retry. GCD completes9,216 tasks, including parking, reuse and idle expiry.

The earlier large-message retry failed because a pending channel notification could precede a modify reply. The new client replaces the actual Mach subscription under its kqueue mutex while retaining the receive right and queued messages; stale readiness reports are dropped when no notification is available. Failed controls remain included. The original bufferless backend and metadata behavior are not presented as complete Darwin API coverage.

The final906-unit source compilation completed, but its original Apple linker timed out. A preserved retry reused exactly those object bytes, verified source differences against the preceding successful plan, accounted for generated MiG timestamp comments and build-directory changes, retried the original linker and verified the resulting export contract. No source compilation was repeated for that recovery.

Original IBAgent now starts its real event pump and passes implicit kqueue initialization. The next observed original assertion is errno78 from kevent_id: syscall375 still lacks a workloop backend. Storyboard compilation and the complete signed App remain incomplete. No checks or original Apple instructions were bypassed.

The opt-in standalone build flag is `--direct-kevent-workqueue`; the corresponding CMake option is `DARLING_DIRECT_KEVENT_WORKQUEUE` and stays off by default. The standalone source builds and native tests are verified. A cold complete Darling CMake build remains unverified. Registration metadata is bounded to1,024 slots, the current default Mach scratch capacity is64 bytes, and arbitrary workloop lifecycle, scheduler QoS, override and FD-reuse semantics require further work. Source, UTF-8 evidence and hashes only; no Apple, Unity, SDK or private binary payloads.
