# Original Unity asset catalog compilation succeeds

The original Xcode `actool` task from the Unity/CocoaPods build now returns 0 on Linux/Darling stage79. It produces a 297,384-byte `Assets.car`, two exported AppIcon PNGs, dependency information and the partial Info.plist. The input asset catalog and original compiler flags are retained; only standalone output destinations differ. Independent host checks validate BOM block boundaries and named trees, 30 rendition tree entries, PNG chunk checksums and 120x120 / 152x152 icon dimensions. Rendering and the individual CAR rendition pixels are not independently verified.

The preceding original-agent failure was a SIGSEGV in libdispatch while merging a vnode event whose userdata was no longer valid. The embedded queue backend had several concrete lifetime defects: registrations ignored `EV_UDATA_SPECIFIC`; disabled `EV_DISPATCH2` deletion lacked `EINPROGRESS` and a terminal deletion acknowledgement; vnode events returned the requested interest mask as if every bit had occurred; closing another handle to an inode corrupted the note flags; and descriptor closure left tagged vnode notes and QoS metadata behind. The source now separates tagged registrations, preserves deferred deletion until acknowledgement, returns actual vnode flags, and cleans up watched descriptors and terminal-event metadata.

Stage79 passes 1,600 rounds with two tagged notes per identity (3,200 terminal acknowledgements), real vnode writes and other-handle closure, and 1,200 watched descriptor close/reuse rounds. The prior stage77 fails the same two-tag test by losing the second event. The first candidate stage78 failed during launchd startup because newly added tree traversal lacked generated pointer-returning function declarations. Its original saved signal context identifies a truncated pointer in `knt_RB_NEXT`; traversal now stays in the translation unit that defines those functions. The intermediate failures are retained. The earlier helper `sys_reboot` formatter has a separate pre-existing secondary fault and was not treated as the root cause.

The paired source changes are pushed to existing `linuxcode/xcode-x86_64` branches as Comman Kang: libkqueue `bd1d346` and XNU `1de8a1f`. The final delta rebuilds 17 queue translation units and reuses 890 objects. New header dependencies include both the canonical queue header and its existing Linux symlink alias; recorded historical bytes are preserved.

Reproduction uses the payload scripts with the recorded private stage and environment. `probe-dispatch2-lifecycle.py` checks the native protocol. `probe-original-assetcatalog.py` extracts the exact failed task from the recorded full-build log and changes only its output paths. `verify-original-assetcatalog-output.py` checks the resulting container without Apple code. These research records do not make the complete historical private runtime reproducible from a clean checkout; the integration installer remains a separate workstream.

The original full Unity/CocoaPods build is being resumed in its existing DerivedData. Full App completion, final App signing, provisioning and device execution are not established by this checkpoint. The sample retains the explicitly documented two-line AFNetworking SDK-header compatibility patch; Xcode project and CocoaPods configuration files are unchanged. Only source, UTF-8 logs and hashes are included here, without Xcode/SDK binaries or generated CAR, NIB, PNG or app products.
