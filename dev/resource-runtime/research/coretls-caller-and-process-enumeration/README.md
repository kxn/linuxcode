# Source CoreTLS caller contexts and real process enumeration

Original macOS Intel UBT progressed beyond NetworkExtension configuration queries and imported tls_handshake_create_for_caller from libcoretls. The pinned original image shows a third caller-name argument, bounded to127 copied bytes, while the old factory forwards a NULL caller. Observed caller-name references are diagnostic/metrics and destruction cleanup. The public Apple source contains the older two-argument factory. The source addition preserves the existing protocol setup and retains the optional label in the opaque context and metrics; it does not assert complete equivalence to modern Apple analytics.

Every31 configured CoreTLS source units is compiled into one coherent backend, preserving300 original exports and adding the factory. The source legacy CoreCrypto ABI is a private libTLSCrypto dependency, with only dylib ID/load metadata renamed and all remaining bytes preserved. Modern CommonCrypto continues using its existing provider. Prepending the old global CoreCrypto instead had caused a missing fault-canary symbol; the failed attempt remains retained. The public libcoretls umbrella now forwards all301 exports to the coherent backend. A first narrow factory-only umbrella let the genuine consumer expose a missing tls_cache_create binding; the full namespace test now resolves all301 symbols through the actual public umbrella.

Four optional caller labels plus the old factory generate genuine TLS1.2 ClientHello messages with an explicitly selected ECDHE-RSA/AES128-GCM suite. Handshake message lengths, version and offered suite are checked, and malformed ServerHello messages are rejected. This is wire-format/startup proof, not a completed TLS handshake or verified server certificate chain. The next genuine UBT invocation enters MSBuild and prints Determining projects to restore, then reports unsupported process enumeration.

The XNU compatibility layer now implements proc_listpids using the actual private namespace procfs. It returns byte counts and the original20-PID allowance for NULL-buffer sizing, handles bounded/unaligned output without overwriting guards, and filters actual PPID, process-group, effective UID and real UID data. Controlling-TTY and XNU kdebug filtering remain explicitly unsupported. Twenty-three native checks exercise live parent/child processes, a separate child process group, user filters, impossible filters, size probing, short buffers and removal after reaping. Only one of907 source kernel units is recompiled;906 are reused. Stage90 is experimental and the real UBT retry is separate evidence.

CoreTLS source is published at1917ba5 in the user's kxn/darling-coretls fork on its existing default master branch, and proc_listpids at9542ee7 in kxn/darling-xnu on linuxcode/xcode-x86_64. All commits use Comman Kang. No original Apple payload, private signing material, license or Epic source is included. Complete UE/App building, developer provisioning, cold reconstruction and full TLS endpoint validation remain unverified.
