# Process-event notifications without stale-readiness deadlock

Passive live stacks from the complete Unity build located CoreServices blocked on the first notification recv in EVFILT_PROC copyout. That synchronous read held up its event pump and therefore a nested xcodebuild SDK query, xcrun --find metal and SwiftPM toolchain initialization. Copyout now uses a nonblocking notification read and drops stale epoll readiness instead of waiting for an unrelated future process event.

The same process channel carries notifications and subscription acknowledgements. Modifying a subscription now drains old notifications while awaiting its correctly sized acknowledgement. The source server rearms notifications after acknowledging the modification, preserving actual queued events and tracked child subscriptions on the same channel. The request now sends the actual Darwin filter flags rather than Linux EPOLLIN, and the successful client update stores those flags for later copyout. No replacing the subscription or synthesizing process exits is used.

The first candidate passed ordinary exit delivery but failed the queued-update test because its local flag copy still described the old subscription. The corrected native session passes 64 queued exit/modification cycles, real child exit statuses, acknowledgement receipts, final event identity/userdata and disable/re-enable retention. NOTE_TRACK preservation is architectural intent, not separately verified by this fixture. The old XNU source filter confirms that a touch replaces the subscribed flags.

To reduce turnaround, the new source-delta builder validates pinned repositories, all recorded headers and every source against the previous complete 907-unit build. It recompiles the single changed proc.c and links with the 906 unchanged objects, keeping old objects, outputs and reports immutable. It records object hashes, commands and explicit changes. The old builder did not record every transitive header dependency; the report explicitly preserves that limitation. Original full-build failures and native negative evidence remain available.

Both source forks are pushed on the existing linuxcode/xcode-x86_64 branches, as Comman Kang. The complete Unity/CocoaPods incremental build is running against stage70 with the same original project and command. Successful final App production is not yet claimed. The previously verified original Storyboard remains recorded in the preceding checkpoint. Only source, UTF-8 text and metadata are included; no private Apple/SDK/product binaries.
