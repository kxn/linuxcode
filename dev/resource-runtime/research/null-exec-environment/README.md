# Original framework tool spawns with an empty environment

After the Unity asset task succeeds, the original full build installs Assets.car and both exported icons into uEmuera.app, then fails embedding libSkiaSharp, libHarfBuzzSharp and UnityFramework. The reported `bitcode_strip` SIGSEGV occurs in the compatibility layer before that original executable starts.

An exact-target spawn capture attached to the original SWBBuildService follows its first bitcode_strip child and records `_execve_internal+0x224` dereferencing NULL. The call stack includes original Foundation `-[NSConcreteTask launchWithDictionary:error:]` and original SWBUtil. That path supplies a NULL environment vector. Explicit-environment standalone execution of the same original tool and framework succeeds, explaining why a simple command-line retry did not reproduce the full-build failure.

The pinned Apple XNU `bsd/kern/kern_exec.c` initializes `ip_envc` to zero and copies environment entries only while `envv != 0LL`. The compatibility layer now normalizes a NULL environment to an empty local vector at exec entry and at spawn entry, before optional binprefs insertion. It deliberately does not inherit the caller's environment. The original tool, project and CI arguments are unchanged.

The old stage79 fails the actual NULL-exec child test. Stage80 passes nine child combinations: direct exec, ordinary spawn and architecture-preference spawn, each with NULL, an explicit empty vector and an explicit inherited vector. The child checks parent sentinel absence/presence and DYLD variable absence for empty environments; the parent checks its own environment remains intact. All nine existing executable-specific environment controls also pass, including exact paths, adjacent nonmatches, UTF-8 values and ENOENT. Finally, original bitcode_strip invoked with a NULL environment returns zero and produces a real output file. The two changed translation units are rebuilt; 905 unchanged objects are reused.

XNU source commit `10b1cc1` is pushed as Comman Kang to the existing `linuxcode/xcode-x86_64` branch. The full original Unity/CocoaPods build is being retried on stage80 in the same DerivedData.
