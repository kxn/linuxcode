# Native Linux Unity licensing and original UE .NET startup

Unity Hub does not need to run under Darling. The official native Linux Unity CLI1.0.0-beta.14 can sign in through a browser on another machine, and supports explicit Personal activation. Linuxcode exposes it through `linuxcode.py unity auth login` and `linuxcode.py unity license activate --personal --accept-eula`. The wrapper pins the official Linux x64 binary SHA256, installs inside runtime only, and passes account/licensing operations to the original CLI. It does not add terms-acceptance flags or record credentials. Existing binary version invocation is verified. The first browser-login attempt timed out without login; a fresh user login and explicit Personal terms confirmation remain necessary. No private OAuth log, login channel or credential store is attached.

Original UE5.8.4 ships macOS Intel .NET10.0.203 / runtime10.0.7. Its CoreCLR GC initialization required kern.memorystatus_level, which was absent in Darling. An original native API probe confirms the missing node while CPU/page queries succeed. The XNU kernel compatibility layer now supplies the read-only available-memory percentage using private Linux procfs MemAvailable/MemTotal. This approximates available pages; it does not implement Darwin jetsam. Short scalar buffers return ENOMEM with zero copied bytes and oldlen0, matching the inspected XNU implementation. Eight native checks, host-reference agreement, and actual original .NET SDK --info succeed. Only one of907 kernel units is recompiled;906 are reused. This experimental stage87 is not adopted into the previously verified Unity v9 profile.

The next genuine UBT build reaches NuGet first-run migration and fails when its named-mutex setup renames a temporary directory under /tmp: Linux renameat returns EXDEV even though both parent descriptors resolve to /state/prefix/private/tmp. A minimal original native directory-rename probe reproduces this. Filesystem/mount diagnosis is next; UBT and UE application builds are not claimed successful. The large whole-bootstrap strace remains private; the minimal trace is retained instead.

XNU source fix is published at ce1ac7f in kxn/darling-xnu, branch linuxcode/xcode-x86_64. Original licensing and runtime source references are recorded in the reports. No native runtime binary, private license, Apple payload or licensed Epic source is included.
